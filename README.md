# سامانه جامع و اختصاصی رستوران، کافه و کترینگ — Flavor

پلتفرم یکپارچهٔ سفارش‌گیری آنلاین و حضوری شامل قالب اختصاصی وردپرس (**Flavor**)، افزونهٔ هستهٔ تجاری (**Flavor Core**) و اپلیکیشن نیتیو موبایل (**Flutter Android & iOS**).

طراحی‌شده از پایه برای رستوران‌ها، کافه‌ها، فست‌فودها، شیرینی‌سراها و کترینگ‌های تشریفاتی با رابط کاربری استاندارد موبایل‌اول، هماهنگی کامل RTL و تایپوگرافی فارسی، هستهٔ قدرتمند سفارش سالن (QR Code میز)، ارسال با پیک و تحویل حضوری، سیستم رزرو میز با تقویم دقیق جلالی، و داشبورد زنده آشپزخانه (KDS).

- **سازگاری فنی**: وردپرس ۶.۴ تا ۷.۱+ · ووکامرس ۸.۵ تا ۱۱.۰+ · PHP ۸.۱ تا ۸.۴ · فلاتر ۳.۲۴+
- **فروش و توزیع تجاری**: متناسب با مارکت‌های معتبر بومی (راست‌چین) و استقرار روی سرورهای مستقل ابری

> این ریپو یک **monorepo** توسعه است. بسته‌های فروش جداگانه می‌مانند:
> `flavor/` قالب و `flavor-core/` افزونه.

نسخه پایدار: **قالب ۱.۶.۲ · هسته ۱.۵.۱**

## این محصول چیست؟

صاحب کافه یا رستوران یک سایت موبایل‌اول می‌گیرد که مشتری از آن منو سفارش می‌دهد (سالن با QR، بیرون‌بر، ارسال)، با موبایل وارد می‌شود و رزرو شمسی می‌کند. آشپزخانه سفارش را روی تبلت می‌بیند.

اگر قالب عوض شود سفارش و شعبه می‌مانند.

## نصب توسعه

```bash
ln -s /path/to/flavor-restaurant/flavor       /path/to/wp/wp-content/themes/flavor
ln -s /path/to/flavor-restaurant/flavor-core  /path/to/wp/wp-content/plugins/flavor-core
```

Flavor Core را فعال کنید؛ اگر ووکامرس نصب نباشد تلاش می‌کند آن را از مخزن رسمی وردپرس نصب و فعال کند. سپس قالب Flavor را فعال کنید. در صورت مسدودبودن نصب خودکار، ابتدا WooCommerce را دستی نصب کنید. پیوندهای یکتا را ذخیره کنید و از **نمایش → دموهای Flavor** یک دمو درون‌ریزی کنید.

## وضعیت بازطراحی دموها

هر ۱۲ پوسته بستهٔ نصب یک‌کلیکی دارد. پنج دموی جدید **لیمو، نوار، فرم، پک و میزان** طراحی اختصاصی دارند؛ هفت طراحی قبلی حفظ شده‌اند. آخرین دموی تکمیل‌شده، **کترینگ و تشریفات سازمانی — میزان (`catering`)** است.

برای نصب، شخصی‌سازی، محدودیت برنامه‌ریز کترینگ و نتایج آزمون‌ها، [راهنمای بازطراحی](docs/DEMO-REDESIGN.md) را ببینید. فونت‌های فارسی محلی‌اند و به دریافت فونت تجاری یا CDN نیازی نیست.

## آزمون‌های خودکار و تضمین کیفیت (Quality Assurance)

پروژه به یک شبکه آزمون خودکار چندلایه‌ای مجهز است که قبل از هر کامیت و در تمامی گردش‌کارهای GitHub Actions اجرا می‌شوند:

```bash
# ۱. آزمون‌های قالب و قراردادهای پوسته‌ها (۶۸ سوئیت تست مجزا)
bash dev-tools/run-theme-tests.sh

# ۲. آزمون‌های منطق خالص هسته (۲۲۶ بررسی امنیتی، تقویم جلالی، توکن‌ها و وب‌هوک)
php flavor-core/tests/run-pure-tests.php

# ۳. آزمون‌های یکپارچگی سرتاسری و سناریوهای سفارش/رزرو/IDOR (۸۲ سناریو)
php flavor-core/tests/run-e2e-integration.php

# ۴. آزمون‌های واحد، ویجت و پوشش کلاینت موبایل فلاتر (۱۶۶ تست + تحلیل استاتیک)
cd mobile && flutter analyze --fatal-infos && flutter test --coverage
python3 dev-tools/check-mobile-coverage.py --threshold 60.0

# ۵. آزمون‌های زیرساخت چندبرندی (White-Label Provisioning)
python3 mobile/scripts/test_provision_brand.py

# ۶. ممیزی ساختاری و زبانی کاتالوگ‌های ترجمه (۱۶۲۳ رشته عربی + فارسی)
bash dev-tools/check-i18n.sh

# ۷. بررسی تطابق نسخه‌ها و هدرهای سازگاری وردپرس و ووکامرس
php dev-tools/check-versions.php

# ۸. ساخت و اعتبارسنجی بسته‌های توزیع خریدار (flavor.zip و demo-pack.zip)
bash dev-tools/build-distribution.sh
```

تمامی آزمون‌ها با معیارهای سخت‌گیرانه (بدون خطا، بدون اخطار، بدون نشت حافظه و با آستانه حداقل ۶۰٪ پوشش خطوط) در خط لولهٔ CI ارزیابی می‌شوند.

## امنیت توکن و دسترسی‌ها (R3-12)

- **هیچ توکنی در مخزن نیست و نباید باشد.** تاریخچهٔ کامل با `git log -p | grep -iE "ghp_|github_pat_|AKIA|webhook_secret"` بازرسی شد (۲۰۲۶-۱۰-۱۲): صفرِ رمزِ واقعی؛ تنها زدن‌ها مثالِ جای‌گدازِ `dev-tools/README-updater.md` و نام‌هایِ شناسه‌اند.
- هر توکنی که در چت/ایمیل/تیکت دیده شده، **لو‌رفته فرض می‌شود**: GitHub → Settings → Developer settings → Personal access tokens → باطلش کنید؛ انقضای کوتاه‌مدت بگذارید و توکنِ جایگزین را فقط در **متغیر محیطی** (ماشین انتشار) یا **Actions Secrets** بگذارید — هرگز در گفتگو نفرستید.
- برای push رباتیک، توکن را از متغیر محیطی به helper بدهید (`GIT_ASKPASS` یا credential helper که `$FLAVOR_PUSH_TOKEN` را می‌خواند) و remote را هرگز با توکنِ درون‌URL تعریف نکنید — توکن در URL، داخل `.git/config` می‌نشیند و همان نشت است. اگر مجبور به یک‌بار‌push دستی شدید، URLِ حاوی متغیرِ env را فقط به‌صورت آرگومانِ همان فرمان بدهید (`git push "https://user:${FLAVOR_PUSH_TOKEN}@…"` با `HISTFILE=/dev/null` یا فضای history پاک‌شده) و بعدش توکن را باطل کنید؛ این تنها شکلِ قابل‌تحملِ موقت است.
- یادداشتِ کاملِ R3-12 در صدرِ [`docs/PREMIUM-MISSION-LIST-2026-10-10-R3.md`](docs/PREMIUM-MISSION-LIST-2026-10-10-R3.md) است؛ سنجهٔ به‌روزرسانی‌های امضاشده: `docs/fa/10-kanal-be-roozrasani.md`.
