## محیط واقعی آزمون

وردپرس دورریختنی `local` با WordPress **7.1.2**، WooCommerce **11.1.2**، PHP **8.4.26**، SQLite Database Integration **3.0.2**، Node **20.20.2**، Playwright **1.63.0** و axe-core **4.13.0**. زبان هستهٔ وردپرس فارسی و پیش‌نمایش راست‌چین بود. این گزارش آزمون staging مشتری، MySQL/MariaDB، Safari، Firefox یا سازگاری عملی تمام نسخه‌های قدیمی‌تر را تأیید نمی‌کند.

### محدودیت مشخص Core mock

این مجموعه کاملاً سبز نیست. همان پنج شکست مبنای قبل از این تغییرات تکرار شدند: محاسبهٔ ظرفیت slots، ایجاد رزرو/guest_token، خواندن با token معتبر، جلوگیری از لغو بدون token و لغو با token معتبر. در این کار، تقویم/ظرفیت واقعی از UI خوانده شد، اما ثبت یا لغو رزرو واقعی انجام نشد. اصلاح این شکست‌ها یا اعتبارسنجی جامع موتور رزرو از نتیجهٔ مثبت رابط استنتاج نمی‌شود.

### مرزهای ایمنی

- هیچ پرداخت یا پیامک واقعی، سفارش مشتری یا ثبت/لغو رزرو واقعی انجام نشد. درخواست SMS، خطای checkout و خطای ویرایش سبد در مرورگر رهگیری شدند؛ ورود از هش Fixture و کوکی واقعی Core عبور کرد.
- سفارش‌های آزمون به‌صورت Fixture علامت‌گذاری‌شده در نصب دورریختنی ساخته شدند؛ وضعیت آن‌ها دادهٔ نمونهٔ آزمون است، نه ادعای تحویل یا پرداخت.
- ویرایش سبد، قیمت ارسالی مرورگر را قبول نمی‌کند. دادهٔ معتبر قبل از تغییر بررسی می‌شود، کلید Woo از انتخاب/یادداشت دوباره ساخته می‌شود و مسیر quantity-only قبلی باقی است. ثبت سفارش، درگاه، مالیات، تخفیف و ارزیابی نهایی checkout جایگزین نشده‌اند.
- تصویر غذا، ساعت یا ظرفیت واقعی کسب‌وکار از ظاهر دمو استنتاج نمی‌شود. فوتر صفحات مشترک فقط ساعت پیکربندی‌شدهٔ شعبه را نشان می‌دهد و نبود ساعت را صریح می‌گوید.
- رمز مدیر تصادفی، OTP و کلیدهای مهمان در `.cache/ui-qa` خصوصی/ignored می‌مانند؛ در GitHub یا این گزارش قرار ندارند. Fixtureهای مدیر، مشتری، شعبه و تغییر موقت افزودنی پس از آزمون پاک/بازگردانده شدند.

## بازتولید

فقط در یک نصب **دورریختنی** `local` یا `development` با WooCommerce و Core فعال، قالب Flavor و پیوندهای یکتای فعال. دستورهای import محتوا/دموی فعلی همین نصب آزمایشی را عوض می‌کنند؛ روی سایت واقعی اجرا نکنید.

```bash
# از ریشهٔ مخزن؛ wp، PHP و Node 20+ باید نصب باشند.
php tests/demos/catalog.php
php tests/ui/tokens.php
FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/ui/cart-edit.php"
FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/ui/setup.php"
FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/demos/currency.php"

# واردکردن هر ۱۲ پوسته و بازگشت به cloud-kitchen؛ این مرحله را قبل از Fixture اجرا کنید.
cd tests/ui
npm ci
npx playwright install --with-deps chromium
FLAVOR_DEMO_QA=1 SITE_URL=https://disposable-wordpress.example/ \
  WP_PATH=/absolute/path/to/disposable/wordpress WP_CLI=/absolute/path/to/wp-cli.phar \
  node skins.mjs
cd ../..

# OTP یک‌بارمصرف است؛ Fixture را قبل از هر اجرای کامل تازه کنید.
FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/ui/editor-fixture.php"
FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/ui/fixtures.php"
FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/ui/admin-fixture.php"
FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/ui/customizer.php"
cd tests/ui
FLAVOR_DEMO_QA=1 SITE_URL=https://disposable-wordpress.example/ UI_STAGE=6 npm test
cd ../..

# پاک‌سازی فقط داده‌های علامت‌گذاری‌شدهٔ آزمون
UI_QA_CLEANUP=1 FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/ui/editor-fixture.php"
UI_QA_CLEANUP=1 FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/ui/fixtures.php"
UI_QA_CLEANUP=1 FLAVOR_DEMO_QA=1 wp eval-file "$PWD/tests/ui/admin-fixture.php"
```

بستهٔ QA دموها در `tests/demos` است؛ برای بررسی صفحهٔ نخست، هر دمو اختصاصی را با `DEMO_SLUG` وارد کنید و از همان پوشه `SITE_URL=… npm test` بزنید. `SITE_URL` اجرای سفارشی‌ساز باید با URL نصب ذخیره‌شده در Fixture مدیر مطابقت داشته باشد. `WP_CLI` در ماتریس، مسیر فایل CLI قابل اجرا با PHP است، نه یک دستور شامل آرگومان.
