# کانال به‌روزرسانی امضاشده و بازگردانی (Flavor)

این راهنما برای **صاحب محصول** و کسی نوشته شده که بسته‌های Flavor را منتشر می‌کند. کانال به‌روزرسانی در نسخهٔ ۱.۶ ساخته شده، اما **به‌صورت پیش‌فرض خاموش است** و تا زمانی که شما سرور و کلید را تعیین نکنید، هیچ درخواست شبکه‌ای ارسال نمی‌کند.

> **وضعیت:** کد، ابزار انتشار، آزمون‌ها و مسیر انتشار روی **GitHub Pages** (در همین مخزن) آماده‌اند. کانال **هنوز روشن نیست**: قبل از فعال‌سازی روی هر سایت باید (۱) کلید عمومی را در `release-site/public.key` commit کنید، (۲) Pages را روی حالت «GitHub Actions» بگذارید، و (۳) یک نسخه را منتشر و بررسی کنید.

---

## ۱. آنچه ساخته شده

| بخش | فایل | کار |
|---|---|---|
| امضا | `flavor/inc/updates/class-update-signature.php` | امضای Ed25519 با libsodium؛ بدون sodium، کانال بسته می‌ماند |
| مانیفست | `flavor/inc/updates/class-update-manifest.php` | خواندن و اعتبارسنجی مانیفست؛ رد downgrade و مهلت گذشته |
| بسته | `flavor/inc/updates/class-update-package.php` | بررسی sha256 و اندازه؛ بررسی ساختار زیپ (ریشه باید `flavor` باشد) |
| پشتیبان | `flavor/inc/updates/class-update-backup.php` | پشتیبان پیش از هر به‌روزرسانی؛ نگهداری ۳ نسخه؛ بازگردانی |
| خطاها | `flavor/inc/updates/class-update-error.php` | پیام‌های فارسی و کد خطای قابل پیگیری |
| اتصال به وردپرس | `flavor/inc/class-update-channel.php` | صفحهٔ تنظیمات، زمان‌بندی روزانه، فیلترهای به‌روزرسانی |
| ابزار انتشار | `dev-tools/release/build-release.php` | `keygen`، `sign` و `verify` (فقط در محیط توسعه/مالک) |
| اسکریپت انتشار | `dev-tools/release/publish.sh` | آزمون، ساخت بسته، کپی، امضا و بررسی یک نسخه روی ماشین مالک |
| سایت عمومی | `release-site/` | فایل‌های عمومی منتشرشده در GitHub Pages (`index.html`، `status.txt`، `public.key`، `flavor/`) |
| Workflow | `.github/workflows/publish-release.yml` | بررسی با کلید عمومی و استقرار `release-site/` روی Pages؛ بدون دسترسی به کلید امضا |
| آزمون | `tests/theme/test-update-channel.php` (۶۴) و `tests/theme/test-release-tooling.php` (۲۹) | هر دو در CI اجرا می‌شوند |

ابزار انتشار و کلید خصوصی **هرگز داخل پوستهٔ فروشی یا روی سایت مشتری نیستند**؛ `build-distribution.sh` فقط پوشهٔ `flavor/` را می‌سازد و `dev-tools/` را شامل نمی‌کند.

## ۲. اصول امنیتی

کانال طوری طراحی شده که در صورت شک، **هیچ به‌روزرسانی‌ای نصب نشود**:

- **بدون libsodium، کانال بسته می‌ماند.** کانال هرگز بدون امضا کار نمی‌کند.
- **امضا قبل از خواندن مانیفست بررسی می‌شود.** مانیفست دست‌کاری‌شده هیچ داده‌ای را به سیستم نمی‌دهد.
- **نشانی بسته باید `https://` باشد.** نشانی `http://` رد می‌شود.
- **مانیفست باید مهلت داشته باشد.** مانیفست منقضی‌شده پذیرفته نمی‌شود؛ این جلوی استفاده از یک مانیفست قدیمی و آسیب‌پذیر را می‌گیرد.
- **downgrade رد می‌شود.** نسخهٔ قدیمی‌تر از نصب‌شده پیشنهاد نمی‌شود.
- **sha256 و اندازهٔ بسته** باید دقیقاً با مانیفست یکی باشد. اگر بسته در مسیر دانلود تغییر کند، نصب نمی‌شود.
- **ریشهٔ زیپ** باید `flavor/` باشد. مسیرهای خارج از پوشه (`..`) و ورودی‌های بیش از حد (بیش از ۵۰۰۰) رد می‌شوند.
- **پشتیبان قبل از نصب.** اگر پشتیبان‌گیری شکست بخورد، به‌روزرسانی **متوقف** می‌شود.
- **کلید عمومی** از یکی از این دو منبع خوانده می‌شود: ثابت `FLAVOR_UPDATE_PUBLIC_KEY` در `wp-config.php` (**توصیه‌شده**) یا گزینهٔ `flavor_updates_public_key` در پایگاه‌داده. اگر ثابت تعریف شده باشد، همیشه بر گزینهٔ پایگاه‌داده برتری دارد.

## ۳. راه‌اندازی روی یک سایت (فقط بعد از انتشار اول)

۱. کلید عمومی (`public.key`، یک خط base64) را در `wp-config.php` قبل از خط `That's all, stop editing!` بگذارید:

```php
define( 'FLAVOR_UPDATE_PUBLIC_KEY', 'کلید-عمومی-base64-اینجا' );
```

۲. در پیشخوان به **نمایش ← به‌روزرسانی Flavor** بروید.
۳. نشانی مانیفست را وارد کنید:

```
https://<owner>.github.io/flavor-restaurant/flavor/manifest.json
```

۴. گزینهٔ **فعال‌سازی کانال به‌روزرسانی** را تیک بزنید و **ذخیرهٔ تنظیمات** را بزنید.
۵. در بخش **بررسی دستی** دکمهٔ **بررسی نسخهٔ جدید** را بزنید تا نتیجه را ببینید.

اگر کلید یا نشانی تنظیم نشده باشد، صفحه دلیل خاموش‌بودن را فارسی نشان می‌دهد. کانال **هیچ درخواستی** نمی‌فرستد تا وقتی همهٔ شرط‌ها برقرار شوند. با خاموش‌کردن کانال، زمان‌بندی روزانه هم پاک می‌شود.

**توجه:** نشانی مانیفست باید دقیقاً همان آدرس بدون redirect باشد. کانال redirect را دنبال نمی‌کند و پاسخ غیر از `200` را رد می‌کند.

### چه زمانی بررسی می‌شود؟

- **روزانه** (زمان‌بندی وردپرس) و با دکمهٔ دستی. هرگز هنگام بازدید صفحه بررسی نمی‌شود.
- اگر نسخهٔ جدیدی باشد، صفحهٔ **به‌روزرسانی‌های** استاندارد وردپرس آن را نشان می‌دهد و همان جریان نصب وردپرس را طی می‌کند؛ قبل از نصب، پشتیبان گرفته می‌شود.

## ۴. انتشار (GitHub Pages)

### الف) یک بار: تنظیمات مخزن و کلید

۱. **تنظیمات Pages:** در GitHub به *Settings ← Pages ← Build and deployment ← Source* بروید و **GitHub Actions** را انتخاب کنید. (اگر API در دسترس باشد، همین کار با `POST /repos/<owner>/flavor-restaurant/pages` و بدنهٔ `{"build_type":"workflow"}` هم انجام می‌شود.)

۲. **ساختن کلید** خارج از مخزن (پوشه را خودتان بسازید؛ مسیر داخل مخزن رد می‌شود):

```bash
mkdir -p ~/flavor-keys && chmod 700 ~/flavor-keys
php dev-tools/release/build-release.php keygen --out=$HOME/flavor-keys
```

۳. **کلید عمومی** را کپی و commit کنید. این فایل عمومی است:

```bash
cp ~/flavor-keys/public.key release-site/public.key
git add release-site/public.key
git commit -m "release: public key"
git push
```

۴. **کلید خصوصی** (`~/flavor-keys/secret.key`) را **هرگز** وارد مخزن، `release-site/`، لاگ، یا ایمیل نکنید. `.gitignore` جلوی `secret.key` و `*.secret.key` و `release-keys/` را در مخزن می‌گیرد، اما بهترین محافظت این است که کلید اصلاً داخل مخزن نباشد. یک نسخهٔ پشتیبان امن هم بسازید؛ اگر کلید گم شود، سایت‌ها به کلید جدید اعتماد نمی‌کنند و باید دستی به‌روز شوند. اگر کلید لو برود، باید کلید جدید بسازید و کلید عمومی را در همهٔ سایت‌ها عوض کنید.

### ب) هر نسخه

۱. نسخه را در `flavor/style.css` و `flavor/functions.php` (هر دو همان مقدار) و همچنین `README.md` و `CHANGELOG.md` به‌روز کنید. `dev-tools/check-versions.php` این‌ها را مقایسه می‌کند.
۲. تغییرات را **commit** کنید. `publish.sh` از ساخت بسته با تغییر کامیت‌نشده در `flavor/` خودداری می‌کند.
۳. اسکریپت انتشار را اجرا کنید (نسخه را خودتان بدهید):

```bash
FLAVOR_RELEASE_SECRET_KEY=$HOME/flavor-keys/secret.key \
FLAVOR_RELEASE_URL_PREFIX=https://<owner>.github.io/flavor-restaurant/flavor/ \
./dev-tools/release/publish.sh 1.7.0
```

این اسکریپت به ترتیب: آزمون‌های کانال و ابزار انتشار را اجرا می‌کند، `dist/flavor.zip` را می‌سازد، آن را به `release-site/flavor/flavor-1.7.0.zip` کپی می‌کند (اگر از قبل باشد، بازنویسی نمی‌کند)، `manifest.json` و `manifest.json.sig` را امضا می‌کند، و **با کلید عمومی** همان بررسی‌ای را انجام می‌دهد که CI انجام می‌دهد. کلید خصوصی هرگز چاپ یا کپی نمی‌شود.

۴. خروجی را بررسی کنید، سپس commit و push کنید:

```bash
git status
git add release-site/flavor
git commit -m "release: flavor 1.7.0"
git push
```

۵. workflow با نام **publish-release** اجرا می‌شود. سه مرحله دارد:
   - **verify:** فایل‌های `release-site/` را بدون کلید خصوصی بررسی می‌کند (امضا، مهلت، sha256، اندازه، ساختار زیپ، نسخه، و پیشوند نشانی).
   - **deploy:** `release-site/` را روی GitHub Pages منتشر می‌کند.
   - **check-live:** هر فایل را مستقیم با `curl` می‌گیرد و باید `200` بدون redirect برگردد.

۶. بررسی دستی (از هر جایی):

```bash
curl -sS -o /dev/null -w '%{http_code} redirect=%{redirect_url}\n' --max-redirs 0 \
  https://<owner>.github.io/flavor-restaurant/flavor/manifest.json
```

خروجی باید `200 redirect=` (بدون آدرس بعد از `=`) باشد.

۷. قبل از اعلام عمومی، کانال را **فقط روی یک سایت آزمایشی** فعال کنید و یک نصب کامل از نشانی https انجام دهید.

### پ) تمدید مهلت مانیفست بدون نسخهٔ جدید

مانیفست پیش‌فرض **۳۰ روز** اعتبار دارد (`FLAVOR_RELEASE_EXPIRES_DAYS`). بعد از مهلت سایت‌ها آن را نمی‌پذیرند؛ این عمدی است تا مانیفست قدیمی دوباره استفاده نشود. اگر نسخهٔ جدیدی نیست، همان زیپ را دوباره امضا کنید:

```bash
php dev-tools/release/build-release.php sign \
  --zip=release-site/flavor/flavor-1.7.0.zip --version=1.7.0 \
  --url=https://<owner>.github.io/flavor-restaurant/flavor/flavor-1.7.0.zip \
  --secret-key=$HOME/flavor-keys/secret.key --out=release-site/flavor --expires-days=30
php dev-tools/release/build-release.php verify --dir=release-site/flavor \
  --public-key=release-site/public.key --url-prefix=https://<owner>.github.io/flavor-restaurant/flavor/
git add release-site/flavor && git commit -m "release: refresh manifest 1.7.0" && git push
```

### ت) نکته‌های مهم

- هر بار که بسته را دوباره بسازید، `sha256` عوض می‌شود. **مانیفست را دوباره امضا کنید**؛ مانیفست قدیمی با بسته جدید هم‌خوان نیست.
- **زیپ‌های منتشرشده در مخزن عمومی می‌مانند** و در تاریخچهٔ گیت باقی می‌مانند. هر کسی می‌تواند آن‌ها را دانلود کند. کدِ قالب هم اکنون در همین مخزن عمومی است؛ اگر قرار است بسته‌ها محرمانه بمانند، باید مخزن را خصوصی کنید یا میزبانی جدا با دسترسی محدود بسازید. این تصمیم با شماست.
- هرگز بسته را بعد از امضا دستی ویرایش نکنید.

## ۵. بازگردانی (rollback)

پشتیبان‌ها در پوشهٔ `wp-content/flavor-backups` نگهداری می‌شوند؛ حداکثر **سه نسخه**. هر بار که قدیمی‌ترین نسخه حذف می‌شود، فقط همان پوشهٔ پشتیبان پاک می‌شود.

برای بازگردانی: **نمایش ← به‌روزرسانی Flavor** را باز کنید، در بخش **بازگردانی نسخهٔ قبلی** پشتیبان موردنظر را انتخاب کنید و دکمهٔ **بازگردانی** را بزنید. بازگردانی به شکل امن انجام می‌شود: اول پوشهٔ جدید کنار گذاشته می‌شود، بعد جایگزین می‌شود، و اگر مرحلهٔ جایگزینی شکست بخورد، خودکار به حالت قبل برمی‌گردد.

## ۶. آنچه هنوز تأیید نشده است (صادقانه)

- **زنجیرهٔ کامل نصب از کانال روی وردپرس واقعی** هنوز اجرا نشده است. نیاز به کلید عمومی تولیدشده، یک انتشار واقعی روی Pages، و یک سایت آزمایشی دارد.
- **workflow انتشار** هنوز روی GitHub اجرا نشده است؛ اولین اجرای آن پس از push این تغییرات و با Pages روی حالت «GitHub Actions» انجام می‌شود.
- آنچه در محیط واقعی (WordPress و WooCommerce) **تأیید شده**: صفحهٔ تنظیمات بدون خطا رندر می‌شود؛ کانال بدون کلید بسته می‌ماند؛ `http://` رد می‌شود؛ زمان‌بندی فقط وقتی کانال روشن است ثبت می‌شود؛ خطای شبکه باعث خطای فاتال نمی‌شود.
- آنچه **با ابزار انتشار و کد تأیید** تأیید شده: خروجی `build-release.php` با همان کد وردپرس تأیید می‌شود؛ دست‌کاری مانیفست، کلید اشتباه، مهلت گذشته، downgrade، sha256 نادرست و ریشهٔ زیپ نادرست همگی رد می‌شوند.

## ۷. ابزار قدیمی GitHub (فقط توسعه)

در `dev-tools/flavor-github-updater.php` یک ابزار قدیمی‌تر هست که پوسته را مستقیم از شاخهٔ `main` گیت‌هاب به‌روز می‌کند و با توکن در `wp-config` کار می‌کند. **این ابزار فقط برای محیط توسعه و استیجینگ است.** روی سایت زنده هرگز آن را نصب نکنید و **همزمان با کانال امضاشده فعال نکنید**: هر دو سعی می‌کنند پوستهٔ یکسان را عوض کنند. برای مشتری فقط کانال امضاشده (یا بستهٔ دستی) مجاز است.

## ۸. تصمیم‌ها

۱. **سرور انتشار:** GitHub Pages در همین مخزن. نشانی: `https://<owner>.github.io/flavor-restaurant/flavor/manifest.json` (مالک را خودتان تنظیم کنید). بدون هزینه.
۲. **نگهدارندهٔ کلید:** مالک، روی ماشین امن خودش. کلید خصوصی هرگز در CI، مخزن یا Pages نیست.
۳. **سیاست انتشار:** هنوز باز است: هر چند وقت یک بار نسخه منتشر شود، و آیا نسخهٔ اضطراری امنیتی جدا داریم؟ مهلت پیش‌فرض ۳۰ روز است (بخش ۴-پ).
۴. **عمومی‌بودن زیپ‌ها:** با توجه به عمومی‌بودن مخزن، زیپ‌ها هم عمومی‌اند (بخش ۴-ت).
