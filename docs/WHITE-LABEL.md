# معماری و راهنمای سیستم وایت‌لیبل (White-Label Mobile System)

این سند معماری، جزئیات فنی و فرآیند عملیاتی سیستم اختصاصی‌سازی برند و ساخت اپلیکیشن موبایل برای چندین مشتری/رستوران بر پایه یک کدبیس واحد (Single Flutter Codebase) را تشریح می‌کند.

---

## ۱. اهداف تجاری و معماری کلان (Architecture Overview)

سیستم وایت‌لیبل **Flavor Mobile** به مجموعه‌های رستورانی، کافه‌ها و کترینگ‌ها این امکان را می‌دهد تا بدون نیاز به توسعه و نگهداری سورس‌کدهای مجزا، اپلیکیشن اختصاصی با هویت بصری، رنگ‌ها، لوگو، آیکون و نام تجاری خود را برای Android و iOS دریافت کنند.

### دیاگرام جریان داده و جداسازی وظایف:

```
+-------------------------------------------------------------+
|                     WordPress Admin (Flavor)                |
|  - نام رستوران، Tenant ID، آیکون، اسپلش، رنگ‌ها، لینک‌ها     |
|  - بررسی خودکار الزامات (Readiness Checklist)                |
|  - ثبت درخواست بیلد (Build Trigger)                         |
+------------------------------+------------------------------+
                               | (REST API / Webhook)
                               v
+-------------------------------------------------------------+
|               Cloud CI/CD (GitHub Actions / Fastlane)       |
|  - مخزن واحد Flutter                                        |
|  - ابزار provision_brand.py جهت تزریق هویت بصری              |
|  - کامپایل نسخه‌های Android APK/AAB و iOS IPA                |
|  - محاسبه هش SHA256 و آپلود آرتیفکت‌ها                       |
+------------------------------+------------------------------+
                               | (HMAC Webhook Callback)
                               v
+-------------------------------------------------------------+
|                   Flavor Build Manager & Dashboard          |
|  - به‌روزرسانی وضعیت (Building -> Success / Failed)          |
|  - نمایش لینک دانلود، متادیتا و حجم فایل‌ها به مدیر رستوران |
+-------------------------------------------------------------+
```

## ۲. مشخصات تنظیمات برندینگ (Tenant Configuration)

تنظیمات هر مستاجر (Tenant) در جدول تنظیمات وردپرس به صورت امن ذخیره شده و از طریق API امن در دسترس خط لوله کامپایل قرار می‌گیرد:

| کلید تنظیمات | نوع | توضیحات |
| :--- | :--- | :--- |
| `restaurant_id` | string | شناسه یکتای مستاجر (مثال: `shandiz_vip`) |
| `app_name` | string | نام اپلیکیشن زیر آیکون و داخل استورها |
| `package_name` | string | شناسه پکیج اندروید (`com.restaurant.shandiz`) |
| `bundle_id` | string | شناسه پکیج iOS (`com.restaurant.shandiz`) |
| `primary_color` | hex | رنگ اصلی برند (مثال: `#C62828`) |
| `secondary_color` | hex | رنگ فرعی (مثال: `#2E7D32`) |
| `accent_color` | hex | رنگ مکمل و تاکیدها (`#FFA000`) |
| `app_icon_url` | url | آدرس آیکون برنامه در سایز 1024x1024 PNG |
| `splash_image_url` | url | آدرس تصویر صفحه اسپلش و خوش‌آمدگویی |
| `default_branch_id`| int | شناسه شعبه پیش‌فرض متصل به اپ |
| `support_phone` | string | شماره تلفن پشتیبانی مشتریان |
| `support_email` | email | ایمیل رسمی واحد پشتیبانی |
| `privacy_policy_url`| url | لینک صفحه حریم خصوصی (الزامی استورها) |
| `terms_url` | url | لینک صفحه قوانین و شرایط سرویس |

## ۳. چرخه تزریق برند در زمان بیلد (Build-Time Brand Provisioning)

اسکریپت پایتون `mobile/scripts/provision_brand.py` وظیفه تطبیق کامل کدبیس را بر عهده دارد:

1. **Flutter Pubspec:** به‌روزرسانی نام برنامه و نسخه نمایشی + بیلد نامبر (`version: 1.0.0+1`).
2. **Android Gradle & Manifest:**
   - تنظیم `applicationId` و `namespace` مطابق با پکیج مستاجر.
   - جایگزینی عنوان برنامه در `android:label` در `AndroidManifest.xml`.
3. **iOS Config & Plist:**
   - به‌روزرسانی `CFBundleDisplayName` در `Info.plist`.
   - تنظیم `PRODUCT_BUNDLE_IDENTIFIER` در پروژه Xcode.
4. **Dart Brand Tokens:**
   - تولید فایل استاتیک `lib/core/constants/brand_tokens.g.dart` شامل مقادیر ثابت رنگ‌ها، آدرس سرور و اطلاعات پشتیبانی تا اپلیکیشن در زمان شروع به سرعت بدون نیاز به ریکوئست اولیه لود شود.

## ۴. تطبیق داینامیک در زمان اجرا (Runtime Theming & Riverpod)

علاوه بر توکن‌های کامپایل، اپلیکیشن در صورت نیاز به تغییرات بلادرنگ (مثل تغییر شماره تماس بدون انتشار نسخه جدید):
- در زمان لود اولیه از اندپوینت `GET /wp-json/flavor/v1/mobile/config` آخرین هویت بصری را دریافت کرده و در `BrandingStateNotifier` ذخیره می‌کند.
- تمام ویجت‌ها از توکن‌های `AppColors` و `Theme.of(context)` تبعیت کرده و به طور کامل با تغییر پالت واکنش نشان می‌دهند.
