# وضعیت Header/Footer Builder در Flavor

تاریخ بررسی: ۲۰۲۶-۱۰-۰۸

## وضعیت فعلی

Header/Footer Builder مستقلِ drag-and-drop در این نسخه پیاده‌سازی نشده است. مسیرهای آمادهٔ مدیریت به‌جای وعدهٔ قابلیت ناقص، به‌صورت مشخص از هم جدا شده‌اند:

- **هدر:** `سفارشی‌سازی → هدر و ناوبری سایت`؛ شامل چینش هدر، ارتفاع لوگو، sticky header، نوار اعلان و منوی WordPress است.
- **پاورقی:** `سفارشی‌سازی → پاورقی و شبکه‌های اجتماعی`؛ شامل لینک‌های اجتماعی، متن کپی‌رایت و ابزارک پاورقی است.
- **صفحه‌ساز:** Builder موجود در ویرایشگر برگه/نوشته/شعبه فقط layout محتوای همان post را مدیریت می‌کند و مالک هدر یا فوتر نیست.
- **انتقال تنظیمات:** `پوسته → پشتیبان تنظیمات` فقط تنظیمات ظاهر و تنظیمات غیرحساس Core را منتقل می‌کند؛ سفارش، مشتری، محصول، رسانه و credential منتقل نمی‌شوند.

## دامنهٔ خارج از این اصلاح

پیاده‌سازی کامل Builder مستقل باید قرارداد جداگانه‌ای برای این موارد داشته باشد: template post type برای header/footer، شرط نمایش بر اساس نوع برگه/شعبه، ترتیب اولویت نسبت به `header.php`/`footer.php`، fallback امن، preview در Customizer، و migration از منوی فعلی. در این مرحله به‌منظور جلوگیری از شکستن هدر فعلی یا حذف منوی کاربر، این دامنه عمداً باز نشده است.

## اصلاحات انجام‌شده در دامنهٔ فعلی

- کنترل‌های typography موجود به فونت heading/body متصل و در انتقال تنظیمات قابل حمل هستند.
- کنترل‌های responsive واقعی برای gutter موبایل/دسکتاپ، اندازهٔ متن پایه، مقیاس تیتر موبایل/دسکتاپ و فاصلهٔ سکشن موبایل/دسکتاپ اضافه شده‌اند.
- مقادیر responsive finite و sanitize می‌شوند؛ CSS با token و media query تولید می‌شود و در Customizer با `postMessage` پیش‌نمایش می‌گیرد.
- مسیر مدیریتِ قابل اعتماد برای هدر/فوتر و لینک آن در Launch Center حفظ شده است.

این فایل وضعیت دقیق مورد بزرگ‌تر را ثبت می‌کند تا «Header/Footer Builder» به‌عنوان قابلیت انجام‌شده گزارش نشود.
