# تست‌های قالب

```
php tests/theme/test-<name>.php      # اجرای یک مجموعه
dev-tools/run-theme-tests.sh         # اجرای همه
```

هر مجموعه خروجی‌اش را با `Results: N Passed, M Failed` تمام می‌کند و در صورت
شکست با کد ۱ خارج می‌شود.

## وابستگی به Flavor Core

قالب به تنهایی قابل تست نیست: کدی که آزموده می‌شود `get_theme_mod()`،
`add_action()` و مانند آن‌ها را صدا می‌زند. تنها بدلِ آفلاینِ نگه‌داری‌شده برای
این توابع در افزونه است — `flavor-core/tests/mock-wp-environment.php`.

این یک **وابستگیِ توسعه است، نه وابستگیِ زمان اجرا**. قالب و افزونه بسته‌های
جدایند و تست‌ها اصلاً روی سایت مشتری نصب نمی‌شوند؛ بنابراین نبودِ افزونه در
یک نصبِ واقعی مشکلی ایجاد نمی‌کند.

اگر افزونه کنار قالب نباشد، مجموعه با پیامی راهنما خارج می‌شود (نه یک fatalِ
PHPِ بی‌نام). برای اشاره به محلِ دیگر:

```
FLAVOR_CORE_DIR=/path/to/flavor-core php tests/theme/test-design.php
```

## افزودن یک مجموعهٔ تازه

1. `bootstrap.php` و fixtureهای لازم را بار کنید.
2. از تابع `check()` همان فایل‌های دیگر الگو بگیرید.
3. نام فایل را با `test-` شروع کنید تا `run-theme-tests.sh` آن را بردارد.
4. در صورت نیاز، یک گام به `.github/workflows/ci.yml` بیفزایید.

## قراردادها

- **توابعِ آینه‌ای را تست کنید، نه متنِ فایل را.** هر جا منطقی در PHP و در
  جاوااسکریپت تکرار شده (`Design::format_px`، `Design::hex2rgb`، فرمولِ WCAG)،
  آزمون تابعِ واقعی را از فایلِ JS استخراج می‌کند، آن را زیر Node اجرا می‌کند و
  خروجی را با PHP مقایسه می‌کند. با هم از هم جدا نمی‌شوند.
- **ثبات‌ها را از خودِ منبع بیازمایید، نه از یک فهرستِ دوم.** مثلاً موجودیِ
  ویجت‌ها از روی فایل‌های `flavor/elementor/widgets/` خوانده می‌شود، و رنگِ
  بندانگشتیِ پوسته با توکنِ همان پوسته مقایسه می‌شود. فهرستِ دستیِ دوم همیشه
  از اصل جدا می‌افتد.
- **پوشش را با دلیل بسنجید، نه با عدد.** یک نسبتِ خام با نسبت‌دادنِ همه‌چیز به
  یک دسته قابلِ دستکاری است.
